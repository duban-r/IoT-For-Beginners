# Підключіть IoT-пристрій до хмари: віртуальний IoT-пристрій і Raspberry Pi

> 👩‍🏫 Цю частину показує викладач (демо). Студенти виконують [локальний варіант](local-mqtt.md).

У цій частині уроку ви підключите віртуальний IoT-пристрій або Raspberry Pi до свого IoT Hub, щоб надсилати телеметрію й отримувати команди.

## Підключіть пристрій до IoT Hub

Наступний крок — підключити пристрій до IoT Hub.

### Завдання: підключіться до IoT Hub

1. Відкрийте папку `soil-moisture-sensor` у VS Code. Якщо ви використовуєте віртуальний IoT-пристрій, переконайтеся, що в терміналі активовано віртуальне середовище.

1. Встановіть додатковий пакет pip:

    ```sh
    pip install azure-iot-device
    ```

    `azure-iot-device` — бібліотека для обміну даними з IoT Hub.

    > 💁 Поточна версія `azure-iot-device` (2.14) працює лише з `paho-mqtt` 1.x, тому pip замінить встановлений `paho-mqtt` 2.x на 1.6.1 і може вивести попередження про конфлікт залежностей. Для цього уроку це не проблема: код пристрою більше не використовує `paho-mqtt` напряму. Якщо потім захочете повернутися до коду з MQTT-брокером, поверніть потрібну версію командою `pip install "paho-mqtt>=2.1"` або створіть для IoT Hub окреме віртуальне середовище.

1. Додайте такий імпорт на початок файлу `app.py`, під наявні імпорти:

    ```python
    from azure.iot.device import IoTHubDeviceClient, Message, MethodResponse
    ```

    Цей код імпортує SDK для обміну даними з IoT Hub.

1. Видаліть рядок `import paho.mqtt.client as mqtt`, бо ця бібліотека більше не потрібна. Видаліть увесь код MQTT: назви тем, весь код, що використовує `mqtt_client`, а також функції `handle_connect` і `handle_command`. Залиште цикл `while True:`, лише видаліть із нього рядок `mqtt_client.publish`.

1. Додайте під імпортами такий код:

    ```python
    connection_string = '<connection_string>'
    ```

    Замініть `<connection_string>` на рядок підключення, який ви отримали для пристрою раніше в цьому уроці.

    > 💁 Так робити не варто. Рядки підключення ніколи не слід зберігати у вихідному коді, бо його можуть додати в систему керування версіями, і тоді рядок знайде будь-хто. Ми робимо так лише для простоти. В ідеалі варто використовувати, наприклад, змінну середовища й інструмент на кшталт [`python-dotenv`](https://pypi.org/project/python-dotenv/). Детальніше про це ви дізнаєтеся в одному з наступних уроків.

1. Під цим кодом додайте такий код, щоб створити об'єкт клієнта пристрою, який обмінюється даними з IoT Hub, і підключити його:

    ```python
    device_client = IoTHubDeviceClient.create_from_connection_string(connection_string)

    print('Підключення')
    device_client.connect()
    print('Підключено')
    ```

1. Запустіть цей код. Ви побачите, що пристрій підключився.

    ```output
    (.venv) ➜  soil-moisture-sensor python app.py
    Підключення
    Підключено
    Вологість ґрунту: 379
    ```

## Надсилання телеметрії

Тепер, коли пристрій підключено, можна надсилати телеметрію в IoT Hub замість MQTT-брокера.

### Завдання: надішліть телеметрію

1. Додайте такий код усередину циклу `while True`, просто перед `time.sleep`:

    ```python
    message = Message(json.dumps({'soil_moisture': soil_moisture}))
    device_client.send_message(message)
    ```

    Цей код створює повідомлення IoT Hub `Message`, що містить показник вологості ґрунту як рядок JSON, і надсилає його в IoT Hub як повідомлення «пристрій — хмара».

## Обробка команд

Пристрій має обробляти команду від серверного коду, яка керує реле. Вона надходить як запит прямого методу.

### Завдання: обробіть запит прямого методу

1. Додайте такий код перед циклом `while True`:

    ```python
    def handle_method_request(request):
        print('Отримано прямий метод:', request.name)

        if request.name == 'relay_on':
            relay.on()
        elif request.name == 'relay_off':
            relay.off()
    ```

    Цей код оголошує функцію `handle_method_request`, яку викликатиме IoT Hub, коли викликається прямий метод. Кожен прямий метод має назву, і цей код очікує метод `relay_on`, щоб увімкнути реле, і `relay_off`, щоб вимкнути його.

    > 💁 Це можна реалізувати й одним прямим методом, передаючи потрібний стан реле в корисному навантаженні (payload), яке надсилається разом із запитом методу й доступне в об'єкті `request`.

1. Прямі методи потребують відповіді, щоб код, який їх викликав, знав, що запит оброблено. Додайте в кінець функції `handle_method_request` такий код, щоб створити відповідь на запит:

    ```python
        method_response = MethodResponse.create_from_method_request(request, 200)
        device_client.send_method_response(method_response)
    ```

    Цей код надсилає в IoT Hub відповідь на запит прямого методу з HTTP-кодом стану 200.

1. Додайте під оголошенням функції такий код:

    ```python
    device_client.on_method_request_received = handle_method_request
    ```

    Цей код повідомляє клієнту IoT Hub, що під час виклику прямого методу потрібно викликати функцію `handle_method_request`.

> 💁 Цей код є в папці [code/virtual-device](code/virtual-device). Код для Raspberry Pi є в [оригінальному курсі](https://github.com/microsoft/IoT-For-Beginners/tree/main/2-farm/lessons/4-migrate-your-plant-to-the-cloud/code/pi) (ще не адаптовано, оригінал англійською).
