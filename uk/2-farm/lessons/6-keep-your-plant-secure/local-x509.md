# Локальний варіант: створіть ключі й сертифікат X.509 за допомогою OpenSSL

У цій частині уроку ви не створюватимете ресурсів в Azure. Натомість ви вручну виконаєте ті самі кроки, які в демо викладача робить за вас команда `az iot hub device-identity create --am x509_thumbprint`: створите пару відкритого й закритого ключів RSA, самопідписаний сертифікат X.509 і подивитеся, що в ньому записано.

Для цього використовується [OpenSSL](https://www.openssl.org) — безкоштовний набір інструментів для роботи з криптографією.

## Підготовка

### Завдання: перевірте, що OpenSSL встановлено

1. Відкрийте термінал і виконайте таку команду:

    ```sh
    openssl version
    ```

    Якщо OpenSSL встановлено, ви побачите його версію, наприклад:

    ```output
    OpenSSL 3.0.13 30 Jan 2024 (Library: OpenSSL 3.0.13 30 Jan 2024)
    ```

1. Якщо команда не знайдена:

    * У Windows OpenSSL входить до складу [Git for Windows](https://git-scm.com/download/win). Виконуйте всі команди цього уроку в **Git Bash**.
    * У macOS OpenSSL (або сумісний з ним LibreSSL) уже встановлено.
    * У Linux встановіть пакет `openssl`, наприклад `sudo apt install openssl`.

1. Створіть папку `x509` і перейдіть у неї:

    ```sh
    mkdir x509
    cd x509
    ```

## Створіть ключі й сертифікат

### Завдання: створіть пару ключів

1. Виконайте таку команду, щоб створити пару ключів RSA завдовжки 2048 біт:

    ```sh
    openssl genrsa -out soil-moisture-sensor-x509-key.pem 2048
    ```

    Буде створено файл `soil-moisture-sensor-x509-key.pem`. Він містить закритий ключ, а з нього завжди можна отримати й відповідний відкритий ключ. Файл починається з рядка `-----BEGIN PRIVATE KEY-----` (або `-----BEGIN RSA PRIVATE KEY-----` у старіших версіях).

    > ⚠️ Зберігайте цей файл у безпеці й не додавайте його в систему керування версіями. Хто має закритий ключ, той може видати себе за ваш пристрій.

### Завдання: створіть самопідписаний сертифікат

1. Виконайте таку команду, щоб створити сертифікат X.509, підписаний вашим власним закритим ключем:

    ```sh
    openssl req -new -x509 -key soil-moisture-sensor-x509-key.pem \
                -out soil-moisture-sensor-x509-cert.pem \
                -days 365 \
                -subj "/CN=soil-moisture-sensor-x509"
    ```

    * `req -new -x509` створює новий сертифікат X.509 і одразу підписує його, а не надсилає запит на підпис у центр сертифікації (CA).
    * `-key` задає закритий ключ, яким підписується сертифікат. Відкритий ключ із цієї пари записується в сам сертифікат.
    * `-days 365` задає термін дії сертифіката: один рік.
    * `-subj "/CN=soil-moisture-sensor-x509"` задає, кому належить сертифікат. `CN` (Common Name) — це ідентифікатор пристрою, той самий, що й у демо викладача.

    > 💁 У Git Bash у Windows рядок `"/CN=..."` може перетворитися на шлях до файлу, і команда видасть помилку. Тоді напишіть на початку два слеші: `-subj "//CN=soil-moisture-sensor-x509"`.

    Буде створено файл `soil-moisture-sensor-x509-cert.pem` — сертифікат X.509 пристрою.

### Завдання: подивіться, що записано в сертифікаті

1. Виконайте таку команду, щоб вивести вміст сертифіката:

    ```sh
    openssl x509 -in soil-moisture-sensor-x509-cert.pem -noout -text
    ```

    Ви побачите поля сертифіката, про які йшлося в уроці:

    ```output
    Certificate:
        Data:
            Version: 3 (0x2)
            Serial Number:
                06:18:e8:ff:bd:b9:9e:3c:16:61:13:1e:4c:37:2d:f7:c2:10:9d:9d
            Signature Algorithm: sha256WithRSAEncryption
            Issuer: CN = soil-moisture-sensor-x509
            Validity
                Not Before: Oct  2 22:24:08 2026 GMT
                Not After : Oct  2 22:24:08 2027 GMT
            Subject: CN = soil-moisture-sensor-x509
            Subject Public Key Info:
                Public Key Algorithm: rsaEncryption
                    Public-Key: (2048 bit)
                    Modulus:
                        00:a7:e3:53:14:84:c8:0b:1a:0b:bd:af:40:58:1a:
                        ...
    ```

    * `Issuer` — хто видав (підписав) сертифікат.
    * `Subject` — кому належить відкритий ключ. У самопідписаному сертифікаті `Issuer` і `Subject` однакові: ви підписали сертифікат самі.
    * `Validity` — термін дії сертифіката.
    * `Subject Public Key Info` — сам відкритий ключ RSA.

1. Перевірте підпис сертифіката:

    ```sh
    openssl verify -CAfile soil-moisture-sensor-x509-cert.pem soil-moisture-sensor-x509-cert.pem
    ```

    ```output
    soil-moisture-sensor-x509-cert.pem: OK
    ```

    Зазвичай у `-CAfile` вказують сертифікат центру сертифікації, якому ви довіряєте. Самопідписаний сертифікат є «сам собі CA», тому його перевіряють ним самим.

1. Виведіть відбиток (thumbprint) сертифіката:

    ```sh
    openssl x509 -in soil-moisture-sensor-x509-cert.pem -noout -fingerprint -sha256
    ```

    ```output
    sha256 Fingerprint=3D:42:A2:40:4C:47:82:F4:ED:5E:A4:4B:C7:F3:E2:45:68:59:02:70:86:0A:FD:3E:D9:D9:38:21:74:C7:9D:A9
    ```

    Відбиток — це хеш сертифіката, короткий «відбиток пальця», за яким його можна впізнати. Саме відбиток зберігає IoT Hub для пристрою, зареєстрованого з `--am x509_thumbprint`: під час підключення пристрій надає свій сертифікат, і IoT Hub порівнює його відбиток зі збереженим.

    > 👩‍🏫 Щоб показати, що такий сертифікат працює з IoT Hub, викладач може зареєструвати пристрій із цим відбитком (без двокрапок) замість автоматично створених файлів: `az iot hub device-identity create --device-id soil-moisture-sensor-x509 --am x509_thumbprint --ptp <thumbprint> --hub-name <hub_name>`. Далі ці файли використовуються в коді пристрою так само, як в інструкції для [віртуального пристрою](single-board-computer-x509.md).

😀 Ви створили пару ключів і самопідписаний сертифікат X.509 для свого пристрою!
